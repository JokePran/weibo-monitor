# 微博监控推送 · 挖地瓜的超级鹿鼎公

在 **A 股交易日交易时段（9:30–15:00，含午休）**，自动监控微博用户「挖地瓜的超级鹿鼎公」(UID 3962719063) 的新微博，一旦有更新就通过 pushplus 推送到你的手机微信。

部署在 GitHub Actions（免费、云端运行、电脑关机也能跑）。

## 工作原理（重要：长驻任务模式）

GitHub Actions 的 `schedule` 定时触发**极不可靠**——会延迟数小时，甚至直接丢弃任务。曾经用"每 5 分钟触发一次"的方案，结果两天只跑了 3 次，且全在半夜，一条都没推出去。

所以现在改用**长驻任务**模式：

1. **一次触发，跑到收盘**：每天 9:15 左右触发一次，启动一个长驻任务，内部**每约 4 分钟**检查一次微博，15:05 收盘后自动退出。
2. **抗延迟**：即使 GitHub 把 9:15 的触发延迟到 10:30 才开始，剩下的盘中时段照样覆盖。
3. **不漏推**：脚本按 `last_mid` 补推——启动时会把"上次之后的所有新微博"一次性补齐，延迟期间漏掉的不会丢。
4. **兜底触发**：另设 10:30、12:50 两个备用触发点，防止主触发被完全丢弃。

其他机制：

- **数据源**：抓取 `sina.cn` 移动版镜像页（服务端渲染，无需微博登录/Cookie）。
- **去重**：每条微博有唯一 `mid`，存于 `state.json`，只推没见过的新微博。
- **时段控制**：判断交易日（周一至周五，排除 2026 年法定休市日）且在 9:30–15:00 内。
- **推送**：pushplus `/send`，HTML 模板，含正文、转发、原文链接。

## 为什么仓库是公开的

GitHub 免费账户的**私有仓库**每月只有 2000 分钟 Actions 额度，而长驻任务每月约需 7000+ 分钟，会超额停跑。**公开仓库的 Actions 免费无限**，所以必须公开。

代码中不含任何密钥——pushplus token 存在仓库 Secrets 里，不会出现在代码或日志中。

## 配置项（已在仓库中配好）

- Secret：`PUSHPLUS_TOKEN` = 你的 pushplus 用户 token
- Actions 权限：Read and write（用于提交 `state.json` 去重状态）

## 手动触发测试

Actions → 微博监控推送 → **Run workflow**。

- 非交易时段触发会立即退出（日志显示"周末休市/已收盘"等），这是正常的。
- 交易时段触发会启动长驻任务，日志里能看到每隔约 4 分钟一次的"执行检查"。

## 维护

- **2027 年**需更新节假日：修改 `monitor.py` 的 `HOLIDAYS_2026` 和 `monitor.yml` 中的 `case` 列表。

## 本地调试

```bash
python3 monitor.py --force --dry-run   # 抓取解析不推送
python3 monitor.py --force --init     # 把当前最新微博设为已读基准
```
